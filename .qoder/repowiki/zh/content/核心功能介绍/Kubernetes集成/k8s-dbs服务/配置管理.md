## 简介
k8s-dbs服务是蓝鲸智云-DB管理系统中的核心组件，负责Kubernetes环境下的数据库服务管理。本配置管理文档全面介绍服务的所有配置项，包括数据库连接配置、第三方API配置和系统常量。文档详细说明配置的格式、加载优先级（环境变量优先）以及配置初始化流程，为系统部署和运维提供指导。

## 配置项详解

### 数据库连接配置
数据库连接配置定义在`dbs_db_config.go`文件中，包含通用数据库配置结构体和特定数据库实例的配置。

**DatabaseConfig 结构体**
该结构体定义了通用的数据库连接参数：

- **Host**: 数据库主机地址，对应环境变量 `HOST`
- **Port**: 数据库端口号，对应环境变量 `PORT`
- **User**: 数据库用户名，对应环境变量 `USER`
- **Password**: 数据库密码，对应环境变量 `PASSWORD`
- **DBName**: 数据库名称，对应环境变量 `DBNAME`
- **TLSMode**: TLS连接模式，对应环境变量 `TLSMODE`
- **MaxOpenConns**: 最大打开连接数，对应环境变量 `MAX_OPEN_CONN`
- **MaxIdleConns**: 最大空闲连接数，对应环境变量 `MAX_IDLE_CONN`
- **MaxLifetime**: 连接最大生命周期（时间类型），对应环境变量 `MAX_LIFETIME`
- **MaxIdleTime**: 连接最大空闲时间（时间类型），对应环境变量 `MAX_IDLE_TIME`

**特定数据库实例配置**
基于通用配置结构体，定义了两个特定数据库实例的配置：

- **DbsDatabaseConfig**: dbs元数据库配置，使用环境变量前缀 `DBS_MYSQL_`
- **AuthDatabaseConfig**: auth元数据库配置，使用环境变量前缀 `AUTH_MYSQL_`

### 第三方API配置
第三方API配置定义在`thirdapi_config.go`文件中，目前包含与DBM系统其他组件通信的API配置。

**ThirdAPIConfig 结构体**
该结构体定义了第三方API的连接参数：

- **DbmAPIURL**: DBM系统API的URL地址，对应环境变量 `DBM_API_URL`

此配置用于k8s-dbs服务与其他DBM组件进行通信，获取必要的元数据和执行跨服务操作。

**Section sources**
- [thirdapi_config.go](file://dbm-services/k8s-dbs/config/thirdapi_config.go#L22-L26)

### 系统常量配置
系统常量配置定义在`system_const.go`文件中，包含系统运行所需的各种常量值。

**核心常量定义**
- **SystemUser**: 系统账户，用于记录系统维护任务的发起人，默认值为 `"system"`
- **AdminUser**: 超级管理员账户，用于记录内部API调用的发起人，默认值为 `"admin"`
- **AdminUserAuthRoleID**: 超级管理员角色ID，用于权限验证，默认值为 `"bkdata.superuser"`
- **EnvLogLevel**: 日志级别环境变量名称，用于通过环境变量控制日志输出级别
- **DefaultLogLevel**: 默认日志级别，当未设置环境变量时使用，当前默认为 `"info"`

这些常量为系统提供了统一的标识符和默认行为，确保系统各组件之间的一致性。

## 配置加载机制
k8s-dbs服务的配置加载机制主要依赖于环境变量，遵循"环境变量优先"的原则。系统在启动时通过反射机制自动将环境变量映射到相应的配置结构体字段。

**配置初始化流程**
服务的配置初始化流程如下：

1. 程序启动时，`main`函数调用`core.Init()`进行核心初始化
2. `core.Init()`进一步调用`InitDB()`初始化数据库连接
3. 在数据库初始化过程中，系统自动读取环境变量并填充配置结构体
4. 配置项通过结构体标签中的`env`和`envPrefix`指定对应的环境变量名称或前缀

**加载优先级**
配置加载遵循以下优先级：
- 环境变量具有最高优先级
- 如果环境变量未设置，则使用代码中定义的默认值（对于有默认值的配置项）
- 系统不支持配置文件方式的配置加载，所有配置均通过环境变量注入

**热更新机制**
当前k8s-dbs服务不支持配置热更新。所有配置在服务启动时读取并初始化，运行时修改环境变量不会影响已运行的服务实例。如需更新配置，必须重启服务。

B --> C[调用InitDB()]

## 配置示例
以下是k8s-dbs服务的完整配置环境变量示例：

```bash
# dbs元数据库配置
DBS_MYSQL_HOST=127.0.0.1
DBS_MYSQL_PORT=3306
DBS_MYSQL_USER=dbs_user
DBS_MYSQL_PASSWORD=secure_password
DBS_MYSQL_DBNAME=dbs_metadata
DBS_MYSQL_TLSMODE=disable
DBS_MYSQL_MAX_OPEN_CONN=100
DBS_MYSQL_MAX_IDLE_CONN=10
DBS_MYSQL_MAX_LIFETIME=3600s
DBS_MYSQL_MAX_IDLE_TIME=300s

# auth元数据库配置
AUTH_MYSQL_HOST=127.0.0.1
AUTH_MYSQL_PORT=3306
AUTH_MYSQL_USER=auth_user
AUTH_MYSQL_PASSWORD=secure_password
AUTH_MYSQL_DBNAME=auth_metadata
AUTH_MYSQL_TLSMODE=disable
AUTH_MYSQL_MAX_OPEN_CONN=50
AUTH_MYSQL_MAX_IDLE_CONN=5
AUTH_MYSQL_MAX_LIFETIME=1800s
AUTH_MYSQL_MAX_IDLE_TIME=150s

# 第三方API配置
DBM_API_URL=http://dbm-api-service:8000/api/v1

# 系统配置
LOG_LEVEL=info
```

在Kubernetes环境中，这些配置通常通过Secret或ConfigMap注入到Pod的环境变量中。

## 配置错误排查
当k8s-dbs服务启动失败或运行异常时，配置问题是最常见的原因之一。以下是常见配置错误的排查方法：

**数据库连接失败**
- 检查环境变量名称是否正确，特别是前缀`DBS_MYSQL_`和`AUTH_MYSQL_`
- 验证数据库主机地址和端口是否可达
- 确认用户名和密码是否正确
- 检查数据库是否允许从服务所在主机进行连接

**第三方API调用失败**
- 验证`DBM_API_URL`环境变量是否设置正确
- 检查网络连通性，确保服务可以访问API地址
- 确认API服务是否正常运行

**日志级别不生效**
- 检查`LOG_LEVEL`环境变量是否正确设置
- 确认环境变量名称大小写是否正确（应为大写）

**通用排查步骤**
1. 检查服务日志，查看启动时的错误信息
2. 验证所有必需的环境变量是否已设置
3. 确认环境变量值的格式是否正确（如端口应为数字，URL应包含协议）
4. 检查Kubernetes Pod的环境变量配置是否正确注入
