## 引言

蓝鲸数据库管理平台（DBM）是一个集成了MySQL、Redis、ES、Kafka、HDFS、InfluxDB、Pulsar等多种数据库组件的全生命周期管理平台，支持海量集群的批量管理能力。该平台提供了完善的DB组件工具箱、个性化配置、高可用切换、域名管理等服务，并具备全方位的监控告警能力，适用于数据库管理员、运维人员和开发人员。

本文档旨在为生产环境中的高可用部署提供详细的实践指南，涵盖资源规划、节点规模、存储配置、网络策略、安全设置、多数据中心部署、跨区域容灾、滚动升级、性能测试及监控告警等关键方面，确保系统稳定、安全、高效运行。

## 资源规划与节点规模建议

在部署蓝鲸DBM系统时，合理的资源规划是保障系统稳定性和性能的基础。根据系统组件的功能和负载特性，建议对不同服务进行差异化资源配置。

### 核心服务资源建议

- **API网关与前端服务（bk-dbm）**：建议配置至少2核CPU、4GB内存，适用于中小型部署；大型部署建议4核CPU、8GB内存以上。
- **数据库配置服务（db-config）**：作为核心配置中心，建议部署2个副本，每个实例配置2核CPU、2GB内存。
- **高可用管理模块（dbha）**：建议部署3个副本以实现高可用，每个实例配置2核CPU、4GB内存，避免单点故障。
- **Kafka消费者服务（bkdata-kafka-consumer）**：根据消息吞吐量调整资源，建议每个实例配置4核CPU、8GB内存，支持水平扩展。
- **Celery任务队列服务（db-celery-service）**：建议根据任务并发量配置，初始部署2个worker，每个配置2核CPU、4GB内存。

### 资源限制与请求配置

在Kubernetes环境中，应为各服务设置合理的资源请求（requests）和限制（limits），防止资源争抢。例如：

```yaml
resources:
  requests:
    cpu: 200m
    memory: 256Mi
  limits:
    cpu: 1000m
    memory: 1024Mi
```

## 存储配置

### 持久化存储

DBM系统中的关键组件需要持久化存储以保障数据安全：

- **MySQL数据库**：用于存储平台元数据，建议使用高性能SSD存储，配置`storageClass`并启用持久卷（Persistent Volume），推荐初始容量8Gi，可根据数据增长动态扩展。
- **Redis缓存**：用于会话和临时数据缓存，建议配置内存存储，不启用持久化以提升性能。
- **日志存储**：各服务日志建议集中存储，配置日志轮转策略，单个日志文件最大100MB，保留3个备份，最长保留30天。

### 配置文件管理

使用ConfigMap管理各服务的配置文件，如`config.yaml`和`logger.yaml`，通过环境变量或卷挂载方式注入容器，便于统一管理和动态更新。

```yaml
envFrom:
  - configMapRef:
      name: bk-dbconfig-db-env
```

## 网络策略与安全设置

### 网络隔离与Ingress配置

建议在Kubernetes集群中启用网络策略（NetworkPolicy），限制服务间的访问权限。对外暴露的服务通过Ingress统一接入，配置如下：

- **Ingress控制器**：使用Nginx Ingress，支持大请求体（`proxy-body-size: 1024m`）。
- **TLS终止**：建议在Ingress层启用HTTPS，配置SSL证书，确保传输安全。
- **真实IP传递**：配置`real_ip_header`和`X-Forwarded-For`，确保后端服务能获取客户端真实IP。

### 安全认证与加密

- **API网关认证**：所有API调用需通过蓝鲸网关进行身份验证和权限控制。
- **数据库连接加密**：敏感服务间通信建议启用SSL/TLS加密。
- **证书管理**：平台提供脚本`make_ssl_pairs.sh`用于生成客户端/服务器SSL证书对，确保服务间安全通信。

```bash
./scripts/make_ssl_pairs.sh
```

## 多数据中心与跨区域容灾方案

### 多数据中心部署架构

DBM支持跨数据中心部署，通过以下方式实现高可用与容灾：

- **主备数据中心**：一个主数据中心处理所有读写请求，备用数据中心通过异步复制同步数据，主中心故障时可手动或自动切换。
- **双活架构**：在两个数据中心同时部署完整服务集群，通过全局负载均衡（GSLB）分发流量，实现故障自动转移。

### 数据同步与一致性

- **配置数据同步**：使用`db-config`服务的高可用模式，确保配置信息在多中心间一致。
- **高可用切换**：`dbha`模块支持自动故障检测与切换，配置`single_switch_interval`（单次切换间隔）和`all_switch_interval`（总切换间隔）防止频繁切换。
- **监控数据采集**：通过`bk-monitor`平台集中采集各中心监控数据，实现统一告警。

```yaml
GQA:
  single_switch_idc: 50
  single_switch_interval: 86400
  all_switch_interval: 7200
```

## 滚动升级策略

### 无中断升级流程

为确保服务连续性，建议采用滚动升级策略：

1. **准备阶段**：备份当前配置和数据库，验证新版本镜像。
2. **分批升级**：每次只升级一个Pod，等待其就绪后再升级下一个。
3. **健康检查**：配置Liveness和Readiness探针，确保新实例正常后再下线旧实例。

```yaml
livenessProbe:
  httpGet:
    path: /ping
    port: http
  initialDelaySeconds: 5
  periodSeconds: 30
readinessProbe:
  httpGet:
    path: /ping
    port: http
  initialDelaySeconds: 5
  periodSeconds: 30
```

### 回滚机制

升级失败时，应能快速回滚到稳定版本。建议：

- 保留至少一个旧版本Pod作为回滚基准。
- 使用Helm版本管理，支持一键回滚。
- 升级前创建数据库快照，确保数据可恢复。

## 性能基准测试与监控指标

### 性能测试建议

- **API响应时间**：核心API（如集群创建、配置查询）P99延迟应小于500ms。
- **并发能力**：系统应支持至少1000 QPS的并发请求。
- **数据库性能**：MySQL实例应能处理每秒1万次查询，Redis支持10万QPS。

### 关键监控指标

| 指标名称 | 说明 | 告警阈值 |
|--------|------|---------|
| CPU使用率 | 服务CPU占用 | >80%持续5分钟 |
| 内存使用率 | 服务内存占用 | >85% |
| 请求延迟 | API响应时间 | P99 > 1s |
| 错误率 | HTTP 5xx错误比例 | >1% |
| 队列长度 | Celery任务积压数 | >100 |
| 数据库连接数 | MySQL活跃连接 | >最大连接数的80% |

监控数据通过Prometheus采集，告警通过蓝鲸监控平台统一管理。

## 常见问题排查指南

### 服务无法启动

- **检查资源配额**：确认Pod是否有足够的CPU和内存资源。
- **查看日志**：检查容器日志，定位启动失败原因。
- **健康探针**：确认Liveness/Readiness探针配置正确。

### 数据库连接失败

- **检查网络策略**：确认服务间网络策略允许通信。
- **验证凭证**：检查数据库用户名、密码是否正确。
- **连接池配置**：调整`maxOpenConns`和`maxIdleConns`避免连接耗尽。

### 高可用切换异常

- **检查配置**：确认`ha.yaml`中`allowed_slave_delay_max`等参数设置合理。
- **监控延迟**：确保主从延迟在允许范围内。
- **手动干预**：必要时可通过API手动触发切换。

### 监控数据缺失

- **检查采集器**：确认`bkmonitorbeat`进程正常运行。
- **验证Data ID**：确保`bk_data_id`配置正确。
- **网络连通性**：检查与监控平台的网络连接。

## 附录

### Helm Chart配置说明

- `global.bkDomain`: 蓝鲸主域名
- `dbm.enabled`: 是否启用DBM核心服务
- `externalDatabase`: 外部数据库连接配置
- `serviceMonitor.enabled`: 是否启用Prometheus监控

### 环境变量说明

- `TRACE_ENABLE`: 是否启用链路追踪
- `LOG_LEVEL`: 日志级别（debug/info/warn/error）
- `ENCRYPT_KEY_PREFIX`: 敏感数据加密密钥前缀
